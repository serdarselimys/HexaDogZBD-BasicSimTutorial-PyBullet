# Fusion 360 → URDF → PyBullet (HexaDog ZBD)

Companion files for the YouTube tutorial on exporting a robot from **Autodesk Fusion 360** and simulating it in **PyBullet**.

This repo gives you two things:

1. `Xacro2URDF.py` — turns the `.xacro` file that the Fusion 360 exporter produces into a plain `.urdf` file, **without needing a ROS 2 installation**.
2. `sim_tutorial.py` — a joint testbench. It spawns the robot in the air and sweeps every joint back and forth so you can see exactly what each physics and motor setting does.

---

## Contents

```
.
├── meshes/                 # STL files for every link of the robot
├── HexaDog_ZBD.xacro       # exported from Fusion 360 (your file)
├── HexaDog_ZBD.urdf        # generated by Xacro2URDF.py
├── Xacro2URDF.py           # xacro -> urdf converter
├── sim_tutorial.py         # PyBullet joint & physics testbench
├── requirements.txt
└── README.md
```

Keep this folder structure. The URDF refers to the meshes with paths like `package://<robot>/meshes/....stl`, so moving `meshes/` will break the visuals.

## 1. Install Python

You need **Python 3.9 or newer**. 3.10–3.12 are the safest choices — PyBullet wheels are not always available for the very newest release on day one.

Check whether you already have it:

```bash
python --version
```

If that fails, try `python3 --version`. If neither works, install it below.

### Windows

1. Go to <https://www.python.org/downloads/windows/> and download the latest **Windows installer (64-bit)** for 3.12.
2. Run the installer.
3. **Tick "Add python.exe to PATH"** on the first screen. This is the single most common thing people miss.
4. Choose *Install Now*.
5. Open a **new** Command Prompt or PowerShell window and confirm:

```powershell
python --version
pip --version
```

> If `pip` is missing: `python -m ensurepip --upgrade`

### macOS

The system Python is old and shouldn't be used. Use [Homebrew](https://brew.sh):

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install python@3.12
python3 --version
```

Or download the official installer from <https://www.python.org/downloads/macos/>.

### Linux (Ubuntu / Debian)

```bash
sudo apt update
sudo apt install python3 python3-pip python3-venv build-essential
python3 --version
```

On Fedora: `sudo dnf install python3 python3-pip gcc gcc-c++`

## 3. Create a virtual environment

A virtual environment keeps these packages away from the rest of your system. Strongly recommended.

**Windows (PowerShell):**

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks the script, run this once and try again:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

**Windows (Command Prompt):**

```cmd
python -m venv .venv
.venv\Scripts\activate.bat
```

**macOS / Linux:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

You'll know it worked when your prompt starts with `(.venv)`. To leave later, type `deactivate`.

PyBullet ships as a compiled extension. If pip tries to build it from source and fails, you're missing a C++ compiler:

- **Windows** — install [Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/), select the *Desktop development with C++* workload, reboot, retry.
- **macOS** — `xcode-select --install`
- **Linux** — `sudo apt install build-essential python3-dev`

## 5. Convert the Xacro to a URDF

The Fusion 360 URDF exporter gives you a `.xacro` file. PyBullet can't read xacro, so convert it first:

```bash
python Xacro2URDF.py
```

Expected output:

```
--- SUCCESS ---
Generated URDF at: .../HexaDog_ZBD.urdf
```

### Using your own robot

Open `Xacro2URDF.py` and edit the two lines at the top:

```python
INPUT_FILE  = "HexaDog_ZBD.xacro"
OUTPUT_FILE = "HexaDog_ZBD.urdf"
```

### How it works

`xacro` normally expects a ROS 2 workspace so it can resolve `$(find <package>)` paths. The script fakes that: it stubs out `ament_index_python` with a mock that always returns the parent folder of this script. That means `$(find your_robot)` resolves to the folder containing `meshes/`, and you never have to install ROS.

Keep the script one level *inside* your package folder if your mesh paths look like `package://robot/meshes/foo.stl`.

## 7. Tuning the simulation

Everything you're meant to touch is in the `CONFIG` block at the top of `sim_tutorial.py`. Change one number, rerun, watch what happens.

### Per-joint sweeps

```python
JOINT_SWEEPS = {
    "FR1": (-30.0, 30.0, 2.0, 0.0),
    #        min    max  period  phase
}
```

- **min_deg / max_deg** — the two ends of the travel
- **period_seconds** — one full there-and-back cycle
- **phase** — `0.0`–`1.0`, offsets where this joint starts. Leave everything at `0.0` and the whole robot moves in unison; stagger them to fake a gait.

Naming on HexaDog is `<leg><number>`:

- legs: `FL ML RL` (left), `FR MR RR` (right)
- number: `1` = shin/knee, `2` = thigh, `3` = hip

Any joint not listed is held at zero. Set a joint to `None` to keep it in the list but frozen.

To isolate one leg:

```python
JOINT_FILTER = ["FL"]     # only joints whose name contains "FL"
```

The script clamps your requested angles to the limits you defined back in Fusion 360 and tells you in the console when it does. If you see a lot of `<- clamped to URDF limits`, your joint limits in Fusion are tighter than you think.

### World

| Setting | What it does |
|---|---|
| `GRAVITY` | set to `0.0` to see joint behaviour with no load |
| `TIMESTEP` | seconds per physics step. Bigger = faster but sloppier. `1/240` is the PyBullet default and a good baseline |
| `FIXED_BASE` | `True` pins the robot in the air. Set `False` to drop it on the ground |
| `SPAWN_HEIGHT` | metres above the plane |

### Contact dynamics

These only matter once `FIXED_BASE = False` and the feet actually touch something.

| Setting | What it does |
|---|---|
| `GROUND_FRICTION` | lateral friction of the plane |
| `ROBOT_FRICTION` | lateral friction of every robot link. Low values = the robot slides around |
| `RESTITUTION` | bounciness, `0.0`–`1.0` |
| `LINEAR_DAMPING` | resists straight-line link motion |
| `ANGULAR_DAMPING` | resists link rotation |

### Motor model

Match these to the servos you actually bought.

| Setting | What it does |
|---|---|
| `MAX_TORQUE` | N·m, roughly your servo's stall torque. Too low and the legs sag under gravity |
| `MAX_VELOCITY` | rad/s ceiling on joint speed |
| `POSITION_GAIN` | how hard the joint pulls toward its target. Higher = snappier, but can oscillate |
| `VELOCITY_GAIN` | how much it resists overshooting. Raise this to damp oscillation |

**A good first experiment:** set `MAX_TORQUE` to something tiny like `0.05`, run it, and watch the tracking error explode. Then walk it back up until the legs keep up. That number is the minimum servo torque your design needs.

## Troubleshooting

**`ModuleNotFoundError: No module named 'pybullet'`**
Your virtual environment isn't active, or you installed into a different Python. Reactivate `.venv` and rerun `pip install -r requirements.txt`.

**`b3Printf: Cannot find file ... .stl` / robot appears as invisible or as plain boxes**
The URDF's mesh paths don't resolve. Check that `meshes/` sits where the URDF expects it and that you ran the script from the repo folder, not from somewhere else. Run `python sim_tutorial.py` with your terminal `cd`'d into the repo.

**The robot explodes, jitters, or flies off screen**
Usually a bad inertia or a self-collision baked into the export. Try a smaller `TIMESTEP` (e.g. `1/480`), then check the `<inertial>` blocks in the URDF for zero or absurd values — Fusion sometimes writes garbage when a body has no material assigned.

**Legs sag and never reach their target**
`MAX_TORQUE` is too low for the mass, or `POSITION_GAIN` is too small. Watch the tracking error line in the terminal.

**Joints move the wrong direction**
Flip the sign order in `JOINT_SWEEPS`, e.g. `(30.0, -30.0, ...)` instead of `(-30.0, 30.0, ...)`. That's exactly why the left legs in the default config are mirrored.

**`xacro is not installed`**
`pip install xacro` inside the active virtual environment.

**Conversion failed with a `$(find ...)` error**
The mock resolves `$(find <pkg>)` to the *parent* of the folder holding `Xacro2URDF.py`. Move the script so that relationship matches your mesh paths, or hardcode `PACKAGE_ROOT` in the script.

**Nothing happens / "Nothing to sweep"**
`JOINT_FILTER` is excluding everything, or `URDF_PATH` points at a file that doesn't exist.

## Using this with your own robot

1. Export from Fusion 360 with the URDF exporter add-in.
2. Drop the resulting `.xacro` and `meshes/` folder into this repo.
3. Edit `INPUT_FILE` / `OUTPUT_FILE` in `Xacro2URDF.py`, run it.
4. Edit `URDF_PATH` in `sim_tutorial.py`.
5. Run `sim_tutorial.py` once with `JOINT_SWEEPS = {}` — it prints every joint the URDF actually contains. Copy those names into your config.
